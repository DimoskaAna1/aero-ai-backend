Questions

Frequently asked questions.

What is Ana?

A multi-tenant chat agent. One backend, one embeddable widget, Android and iOS bubbles.

How does it work?

The widget posts to /api/v1/chat with X-Tenant-Id and X-Tenant-Key. Catalog turns stay in flow.py. Other turns retrieve tenant_knowledge.

How much does it cost?

Demo keys are free. New tenants start at 500 messages / month unless you raise the limit in Supabase.

Do I need to code?

Paste the script from /admin. The shop page listens for b2b-ai:cart if you want a cart.

Which model?

Menu and price search do not call OpenAI. Other turns use the configured LiteLLM model when a key is present.

Can I use my own backend?

Yes. The widget is a client. Catalog logic stays on this API so clients do not duplicate it.

Is data isolated?

Knowledge, usage, keys and bookings are filtered by tenant_id. The header must match the body tenant.

Data and compliance

Tenant rows stay on your tenant.

Your data stays yours

Ingest writes tenant_knowledge for that tenant only. Foreign tenant_id rows are dropped on read.

Keys on the wire

Chat requires matching X-Tenant-Id and X-Tenant-Key. CORS is * with credentials off.

No invented stock

If the catalog has no match, the reply says so. Prices come from the product row.

Ready to put the agent on a shop?
